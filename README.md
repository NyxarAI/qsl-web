## 功能特性

### 通联日志（QSO）

- 完整通联字段：日期时间（本地 + UTC 双时间自动填写）、频率、波段、模式、
  信号报告、对方呼号、本台设备、对方设备/天线、中继台、对方功率、
  地址、邮箱、CQ/WW 分区、网格、备注
- 频率 ↔ 波段自动联动，超范围标"自定义"
- 信号报告按模式区分：语音 59 式、CW/RTTY 三位 RST、FT8/FT4 用 SNR（dB）
- 2m / 70cm 快捷频率按钮
- 本台设置支持多套设备方案，每条 QSO 保存本台快照
- 表格 / 卡片双视图一键切换（右上角图标，偏好自动记忆）
- 搜索、批量删除、批量设 QSL 状态

### QSL 卡片管理

- 三栏工作台：待寄出 / 运输中·待回卡 / 已收卡
- 每张卡片记录快递单号、邮资、寄送地址
- 三栏均支持多选 + 批量设状态
- 设为"已寄"时可一键发送 QSL 寄出通知邮件

### 邮件通知

- 两个触发点：新增 QSO 后发确认邮件，QSL 设为已寄时发寄出通知
- 邮件模板管理：主题 + 正文，支持 31 个模板变量
  （呼号、日期、频率、波段、模式、双方设备、对方功率、中继台、
  快递单号、邮资、QSL 地址等全部 QSO 字段）
- 先保存业务数据再发邮件：邮件失败不影响 QSO/QSL 落库
- 邮件发送记录：成功/失败可查，失败可一键补发

### 呼号查询

- QRZ 呼号查询（网页抓取路线），自动填充对方地址、邮箱、网格、分区
- 查询结果 30 天缓存
- 查询结果一键填入 QSL 寄送地址

### 数据管理

- ADIF 导入 / 导出（标准业余无线电日志格式）
- JSON 备份 / 恢复
- 网站操作日志（登录、QSO、QRZ、邮件、导入导出，倒序 500 条）
- 公开只读通联日志（管理员可开关，只显示基本信息）

### 界面

- 桌面 + 手机端适配（390px 视口可用）
- 表格视图：真表头、列对齐、表头置顶、窄屏横向滚动

技术栈：Bun + SQLite（单文件数据库）+ React。

## 快速开始

### Docker 运行

```bash
docker run -d \
  --name qsl-web \
  --restart unless-stopped \
  -p 8091:8080 \
  -v /opt/qsl-web/data:/app/data \
  -e TZ=Asia/Shanghai \
  nyxarai/qsl-web:latest
```

打开 `http://服务器IP:8091`，首次进入设置管理员密码（至少 8 位）即可使用。

> 把 `<你的DockerHub用户名>` 换成实际的镜像名。

### docker compose（推荐）

```yaml
services:
  qsl-web:
    image: nyxarai/qsl-web:latest
    container_name: qsl-web
    restart: unless-stopped
    ports:
      - "8091:8080"
    volumes:
      - /opt/qsl-web/data:/app/data
    environment:
      TZ: Asia/Shanghai
```

```bash
docker compose up -d
```

## 使用指南

### 初次设置

1. 打开网站，按提示设置管理员密码
2. 进「设置」→「本台设置」：填写你的呼号、QTH（操作地点/网格）、
   添加常用设备方案（收发机、天线、功率）
3. 「设置」→「SMTP」：填写发件服务器信息（见下文），点"测试发送"验证
4. 「设置」→「QRZ」：填写 QRZ 账号密码，用于呼号查询

### 记录一次通联

1. 点底部「+ 记台」，填写通联信息
2. 频率输入后波段自动联动；信号报告按所选模式自动切换格式
3. 对方呼号可点"查询"从 QRZ 获取地址信息
4. 保存后如对方有邮箱，会弹窗询问是否发送 QSO 确认邮件
   （可在设置里换模板；无邮箱不弹窗）

### QSL 卡片流程

1. 进「QSL 卡片台」，通联按状态分列在三栏中
2. 点卡片填写寄送地址（可从 QRZ 查询结果一键填入）、快递单号、邮资
3. 点卡片状态或批量多选 → 设为"已寄"：
   如对方有邮箱，会弹窗确认是否发送 QSL 寄出通知邮件
4. 「邮件记录」区块查看每封邮件的发送状态，失败的可一键补发

### 邮件模板

「设置」→「邮件模板」：可新增、编辑、删除模板，预置"QSO 确认"和
"QSL 寄出通知"两个默认模板。主题和正文都支持变量，空值显示"—"。

可用变量（31 个，覆盖全部 QSO 字段）：呼号、日期 UTC、日期本地、
时间 UTC、时间本地、频率、波段、模式、信号报告、对方信号报告、
我方呼号、我方设备、我方天线、我方功率、对方设备、对方天线、对方功率、
中继台、对方 QSL 地址、QSL 状态、快递单号、邮资、备注、网格、
CQ 分区、ITU 分区、国家/地区等。设置页有完整变量说明。

### QRZ 查询配置

「设置」→「QRZ」填写 qrz.com 的用户名和密码（加密存储在服务端）。
查询走网页抓取路线，需要 QRZ 付费订阅账号；查询结果缓存 30 天。

### SMTP 配置

「设置」→「SMTP」填写：服务器地址、端口、加密方式（465 隐式 TLS /
587 STARTTLS）、发件邮箱、用户名、授权码。填完务必点"测试发送"。

> 注意：部分云服务商（及某些家用宽带）会拦截 25/465/587 端口的出站
> SMTP 连接，表现为连接超时或握手失败。这种情况建议改用服务商的
> HTTP 邮件 API（如阿里云 DirectMail）。

### 公开日志

「设置」里可打开"公开通联日志"，访客无需登录即可查看（只显示
QSO 基本信息，不暴露地址、邮箱、备注、设备信息）。

## 配置参考

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8080` | 容器内监听端口 |
| `DB_PATH` | `/app/data/app.db` | 数据库文件路径 |
| `DRIZZLE_DIR` | `/app/drizzle` | 迁移脚本目录 |
| `TZ` | — | 时区，建议 `Asia/Shanghai` |

### 数据持久化

数据库是 SQLite 单文件，通过 volume 挂在宿主机的 `/opt/qsl-web/data/app.db`。
容器里只跑应用（不含 nginx）；需要域名/HTTPS，在前面加一层反向代理
指向 `127.0.0.1:8091` 即可。

### 升级

```bash
docker compose pull && docker compose up -d
```

数据库 schema 变更会在容器启动时自动迁移，无需手动操作。
升级前建议先备份数据库（见下）。

### 备份与恢复

```bash
# 备份（WAL 模式下先停服再拷最稳）
docker stop qsl-web
cp /opt/qsl-web/data/app.db /root/app.db.备份-$(date +%Y%m%d)
docker start qsl-web

# 恢复
docker stop qsl-web
cp /root/app.db.备份-xxxx /opt/qsl-web/data/app.db
docker start qsl-web
```

另外推荐定期用站内的 JSON 备份功能再存一份异地备份。

## 常见问题

**端口被占用？**
把 `-p 8091:8080` 的 8091 换成别的端口。

**忘记管理员密码？**
停止容器后删除 `/opt/qsl-web/data/app.db` 重建（会清空所有数据）。
有备份的话恢复备份文件即可。

**QRZ 查询失败？**
检查设置页的 QRZ 账号密码；QRZ 登录页有反爬机制，查询失败时
应用会返回真实错误信息，按提示处理。

**邮件发送失败？**
先看「QSL 卡片台」→「邮件记录」里的错误信息；常见原因是 SMTP 端口被
云服务商拦截（见上文 SMTP 配置说明）。失败的邮件可以一键补发，
业务数据不受影响。

**如何清空全部数据重新开始？**
停止并删除容器，清空 `/opt/qsl-web/data/` 目录后重建容器。

**备份的数据库能直接用 SQLite 打开吗？**
可以，`app.db` 就是标准 SQLite 文件，任何 SQLite 工具都能打开查看。
